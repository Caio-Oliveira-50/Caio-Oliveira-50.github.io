SQL Analítico Avançado

Análise de Retenção de Clientes (Cohort) & Churn de E-commerce

Cálculo de taxa de recompra e retenção mensal utilizando CTEs encadeadas e Window Functions em uma base de 50.000+ transações.

Ver no GitHub

O Problema

A equipe comercial precisava entender se o aumento de receita vinha de novos clientes ou da retenção dos clientes antigos, e em qual mês acontecia a maior perda de compradores (churn prematuro).

Solução Técnica

  • Construção de uma safra (Cohort) baseada na data da primeira compra via MIN() e DATE_TRUNC.
  • Cálculo do intervalo em meses entre as compras subsequentes usando EXTRACT.
  • Utilização de Common Table Expressions (CTEs) para modularizar e tornar a consulta legível e performática.
PostgreSQL / SQL 
-- Análise de Retenção de Clientes por Safra Mensal (Cohort)
WITH primeira_compra AS (
    SELECT 
        cliente_id,
        DATE_TRUNC('month', MIN(data_pedido)) AS mes_safra
    FROM pedidos
    GROUP BY cliente_id
),
atividades_pedidos AS (
    SELECT 
        p.cliente_id,
        pc.mes_safra,
        DATE_TRUNC('month', p.data_pedido) AS mes_pedido,
        (EXTRACT(year FROM p.data_pedido) - EXTRACT(year FROM pc.mes_safra)) * 12 +
        (EXTRACT(month FROM p.data_pedido) - EXTRACT(month FROM pc.mes_safra)) AS mes_offset
    FROM pedidos p
    INNER JOIN primeira_compra pc ON p.cliente_id = pc.cliente_id
)
SELECT 
    TO_CHAR(mes_safra, 'YYYY-MM') AS safra,
    COUNT(DISTINCT CASE WHEN mes_offset = 0 THEN cliente_id END) AS clientes_iniciais,
    ROUND(COUNT(DISTINCT CASE WHEN mes_offset = 1 THEN cliente_id END)::numeric / 
          NULLIF(COUNT(DISTINCT CASE WHEN mes_offset = 0 THEN cliente_id END), 0) * 100, 1) AS retencao_mes_1,
    ROUND(COUNT(DISTINCT CASE WHEN mes_offset = 2 THEN cliente_id END)::numeric / 
          NULLIF(COUNT(DISTINCT CASE WHEN mes_offset = 0 THEN cliente_id END), 0) * 100, 1) AS retencao_mes_2
FROM atividades_pedidos
GROUP BY mes_safra
ORDER BY mes_safra;

Pipeline ETL Automatizado para Ingestão e Validação de Vendas

Script em Python que consome dados brutos de filiais em CSV/JSON, realiza limpeza e tipagem com Pandas e persiste os dados em banco SQLite/Postgres com SQLAlchemy.

Ver no GitHub

O Problema

Arquivos diários de vendas chegavam de diferentes filiais com formatos divergentes, campos nulos e duplicatas, provocando erros nas consultas e relatórios.

A Arquitetura

Pipeline automatizado em Python usando Pandas para tipagem e higienização, e escrita otimizada no banco via SQLAlchemy (to_sql com chunksize).

Python 3 & Pandas 
# etl_pipeline.py - Extração, Limpeza e Carga Relacional
import pandas as pd
from sqlalchemy import create_engine

def executar_etl(caminho_csv, db_uri):
    # 1. Extração
    df = pd.read_csv(caminho_csv)
    
    # 2. Transformação e Limpeza
    df['data_pedido'] = pd.to_datetime(df['data_pedido'], errors='coerce')
    df = df.dropna(subset=['cliente_id', 'valor_total'])
    df['valor_total'] = df['valor_total'].apply(lambda x: max(x, 0.0))
    
    # 3. Carga no Banco Relacional (SQLite / PostgreSQL)
    engine = create_engine(db_uri)
    df.to_sql(
        name='pedidos_consolidados',
        con=engine,
        if_exists='append',
        index=False,
        chunksize=1000
    )
    print(f"Sucesso: {len(df)} registros processados e inseridos.")

if __name__ == "__main__":
    executar_etl("vendas_raw.csv", "sqlite:///empresa.db")

Engenharia & Modelagem de Dados

Modelagem de Banco de Dados de Logística (Normalização 3FN)

Arquitetura de dados relacional desenhada para suportar alta concorrência, normalizada em 3ª Forma Normal, com índices B-Tree e Views analíticas.

Ver no GitHub

O Problema

Uma base de entregas misturada causava anomalias de atualização e consultas com alto custo de processamento em relatórios operacionais.

Solução de Arquitetura

Separação em entidades normalizadas: clientes, entregadores, pedidos e historico_entregas com integridade referencial estrita e índices estratégicos.

SQL DDL & Views 
-- Modelagem Relacional & Otimização de Consultas
CREATE TABLE entregadores (
    entregador_id SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    veiculo_tipo VARCHAR(30),
    ativo BOOLEAN DEFAULT TRUE
);

CREATE TABLE historico_entregas (
    entrega_id SERIAL PRIMARY KEY,
    pedido_id INT REFERENCES pedidos(pedido_id) ON DELETE CASCADE,
    entregador_id INT REFERENCES entregadores(entregador_id),
    status VARCHAR(20) CHECK (status IN ('pendente', 'em_rota', 'concluido', 'falha')),
    data_atualizacao TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Índice B-Tree para buscas rápidas de pedidos ativos por entregador
CREATE INDEX idx_entregas_status_entregador 
ON historico_entregas (entregador_id, status);

-- View para relatório executivo de SLA de entregas
CREATE VIEW vw_desempenho_entregadores AS
SELECT 
    e.nome,
    COUNT(h.entrega_id) AS total_atribuido,
    SUM(CASE WHEN h.status = 'concluido' THEN 1 ELSE 0 END) AS entregas_sucesso
FROM entregadores e
LEFT JOIN historico_entregas h ON e.entregador_id = h.entregador_id
GROUP BY e.entregador_id, e.nome;
